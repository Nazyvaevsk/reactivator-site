# Ручная выдача доступа после оплаты

1. Покупатель отправляет заявку с карточки комплекта. Сервер проверяет отдельный groupId по приватному индексу и сам формирует модель, комплект и цену 590 ₽.
2. В MASTER_CHAT_ID приходит уведомление с URL-кнопкой «Выдать доступ на 24 часа» и резервной текстовой ссылкой.
3. Мастер проверяет оплату вручную, открывает кнопку, проверяет комплект и нажимает «Оплата получена — создать и скопировать ссылку».
4. Сервер создаёт HMAC-ссылку на /body-dimensions/access для этого groupId на 86400 секунд от момента выдачи. Мастер отправляет её клиенту. Если браузер Telegram запрещает автокопирование, есть отдельная кнопка и поле для ручного копирования.

## Настройка Vercel

Добавить серверную переменную BODY_DIMENSIONS_ISSUE_SECRET: отдельное случайное значение не короче 32 символов (рекомендуется 32 случайных байта в hex). Не использовать префикс NEXT_PUBLIC. Значение не входит в репозиторий.

Установить BODY_DIMENSIONS_BASE_URL=https://reactivator-site.vercel.app (либо актуальный основной HTTPS-домен без пути). Ссылки и проверка Origin используют именно этот адрес; Host и пользовательский ввод не используются. Домен должен обслуживать этот deployment, не перенаправлять на другой origin.

Сохранить существующие BODY_DIMENSIONS_ACCESS_SECRET, MASTER_CHAT_ID, RELAY_SECRET и настройки R2. Выполнить redeploy после настройки. Если конфигурация отсутствует, покупка возвращает ошибку 503, а доступ не выдаётся. CLI scripts/create-body-access.cjs сохранён как резерв.

## Cloudflare / Telegram

Webhook и callback_query не требуются. Исходники действующего worker в проекте отсутствуют; его контракт нужно проверить при развёртывании. Relay должен сохранять проверку X-Relay-Secret и отправлять запрос только в разрешённый MASTER_CHAT_ID. Для inline-кнопки он должен передавать Telegram поля reply_markup (JSON-строка) и disable_web_page_preview из FormData вместе с chat_id и text. Если worker собирает поля по списку, добавить эти два поля. Если уже пересылает FormData целиком, изменений не требуется.

Резервная подписанная ссылка остаётся в тексте, поэтому открыть страницу можно и когда relay отбрасывает reply_markup. Relay не должен включать parse_mode для пользовательского текста. Возвращать upstream JSON Telegram с ok и HTTP-статусом, чтобы ошибки доставки определялись сервером. Не логировать тела заявок, заголовок секрета или подписанные ссылки.

Никакие сообщения и изменения инфраструктуры автоматически при разработке не выполняются. После deployment отправить тестовую заявку S04435 и проверить доставку кнопки/резервной ссылки в реальном Telegram, копирование на телефоне и открытие клиентского комплекта/ZIP из R2.

## Границы защиты

Служебная ссылка — bearer-доступ: любой её обладатель может выдавать доступ только указанному комплекту в течение 7 дней. Это не проверка Telegram-личности и не проверка оплаты. MASTER_CHAT_ID криптографически привязан к подписи, но пересылку ссылки это не предотвращает. Чат мастера должен быть закрытым; служебную ссылку нельзя отправлять клиенту.

Токен имеет отдельный HMAC-контекст и секрет, срок, groupId и случайный идентификатор. Токен находится после #, не передаётся GET-запросом и удаляется из адресной строки страницы. POST передаёт его серверу. Страница отдельная, без аналитики, с CSP, no-store, no-referrer, запретом встраивания и индексирования. Открытие URL и Telegram preview не создают клиентскую ссылку. Секреты остаются на сервере.

Без базы данных служебная ссылка не одноразовая: повторное открытие и явное нажатие могут выдать новую ссылку. Копирование уже созданной ссылки срок не продлевает. Одноразовость, журнал оплат и отзыв отдельных ссылок не реализованы. Ротация ISSUE_SECRET отзывает все служебные кнопки; ACCESS_SECRET — все клиентские ссылки. После истечения служебной кнопки использовать CLI. Публичная форма сохраняет прежние ограничения защиты от спама; подпись в ответ покупателю никогда не возвращается.
