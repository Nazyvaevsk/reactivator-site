3. ПРОВЕРКА СЕРВЕР САЙТА → CLOUDFLARE
==================================================

Linux shell на действующем сервере сайта (Timeweb не является обязательной платформой):

curl -i --connect-timeout 5 --max-time 10 https://reactivator-telegram-relay.nazyvaevsk.workers.dev

Нормальный ответ:
HTTP 200
Reactivator Telegram Relay OK


==================================================
4. ПРОВЕРКА RELAY_SECRET НА СЕРВЕРЕ САЙТА
==================================================

Linux shell на сервере, если приложение работает как PID 1 и доступен /proc/1/environ. Проверка наличия переменной без вывода значения:

tr '\0' '\n' < /proc/1/environ | grep -q '^RELAY_SECRET=' && echo SET || echo EMPTY

Норма:
SET


==================================================
5. ПРОВЕРКА ПРЯМОГО ДОСТУПА СЕРВЕРА К TELEGRAM
==================================================

Linux shell на сервере, только для диагностики:

curl -4 -I --connect-timeout 5 --max-time 10 https://api.telegram.org

Ранее на Timeweb Москва было:
Timeout

Это исторический результат, а не обязательное поведение текущего сервера. Сайт использует Cloudflare Relay.

9. ЕСЛИ ФОРМА НЕ ОТПРАВЛЯЕТСЯ
==================================================

Порядок проверки:

1. Сайт открывается?
2. Деплой на текущей платформе успешно завершён?
3. RELAY_SECRET = SET?
4. Worker отвечает?
5. В логах сервера сайта есть Relay sendMessage error / Relay sendPhoto error?
6. В Cloudflare есть TELEGRAM_TOKEN и RELAY_SECRET?
7. Совпадает ли RELAY_SECRET на сервере сайта и Cloudflare?
8. Telegram-бот жив?

10. ЕСЛИ НУЖЕН ОТКАТ API
==================================================

PowerShell (локально), сначала только просмотр Git:

git status
git log --oneline -- app/api/send-telegram/route.ts
git diff -- app/api/send-telegram/route.ts

Выбрать проверенный коммит из истории, учитывая совместимость с текущим Relay.
Заменить ПРОВЕРЕННЫЙ_КОММИТ на его хеш; посмотреть версию и отличия:
git show 'ПРОВЕРЕННЫЙ_КОММИТ:app/api/send-telegram/route.ts'
git diff ПРОВЕРЕННЫЙ_КОММИТ -- app/api/send-telegram/route.ts

Только после отдельного подтверждения пользователя и сохранения нужных локальных
изменений восстановить файл из Git (команда перезапишет рабочую копию файла):
git restore --source=ПРОВЕРЕННЫЙ_КОММИТ --worktree -- app/api/send-telegram/route.ts

Проверить diff и сборку. Индексация, коммит и push — отдельные подтверждаемые действия.


==================================================
11. R2 — ПРОВЕРКА СХЕМЫ ДОСТУПА
==================================================

Оригиналы приватные; превью публичные.
Сайт использует только read-only доступ через R2_ACCESS_KEY_ID и R2_SECRET_ACCESS_KEY.
Временные upload-токены Read & Write уже отозваны, старые upload-ключи удалены из .env.local.
Не восстанавливать отозванные ключи и не запускать загрузку для проверки чтения.
Проверять наличие переменных в настройках действующего сервера без вывода значений.
Значения секретов не копировать в документацию, отчёты или Git.
